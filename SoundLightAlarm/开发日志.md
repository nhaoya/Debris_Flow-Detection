# 声光报警器开发日志

> 更新：2026-08-26

## 一、今天做了什么

### 1. LoRa 模块资料与供电排查（DX-LR32-433T22D）

- 阅读官方资料（技术手册 + 串口应用指导）：
  - 引脚：1=M0、2=M1、3=RX、4=TX、5=AUX、6=VCC、7=GND
  - 官方典型应用电路：**VCC 用 5V**，M0/M1 接 MCU IO，VCC 处并 22µF+0.1µF
  - 官方例程思路：**透明传输模式(MODE0)，不做 AT 配置**，MCU 只收发数据
- 用智谱视觉模型识别接线照片和文档电路图（两次识别结果有出入，最终靠万用表实测确认）

### 2. 接收端固件（STM32F103C8T6，Keil SPL 工程）

- 工程结构：`Hardware/`（usart/usart2/usart3/LoRa/JQ8X00/LED）、`System/`（Delay）、`User/`（main）
- 新增：
  - `Hardware/usart2.c`：USART2(PA2/PA3) 驱动，LoRa 用，9600 8N1 中断接收
  - `Hardware/usart3.c`：USART3(PB10/PB11) 调试串口，打印日志用
  - `Hardware/LoRa.c/h`：透明传输接收 + `ALM|` 帧解析
  - LED 调试指示：收到任何数据 LED(PB0) 闪一下
- **最终重写为纯透明传输版**：删掉所有 AT 自动配置代码，模块用出厂默认参数直接收发
- **实现多节点报警状态机**（main.c）：
  - 每帧带节点号 `ALM|N1|1|...`，接收端维护各节点状态（3 帧防抖）
  - IDLE（无报警）/ WARNING（部分报警，不上报）/ CONFIRMED（全部报警，4G 上报）
  - `ReportToServer()` 已留接口，Air780E 接入后实现

## 二、踩过的坑（重要）

| # | 坑 | 结论 |
| --- | --- | --- |
| 1 | **LoRa 模块供电电压** | 标称 3.3~5.5V，但实测 **3.3V 不工作**，必须真 5V（官方电路也是 5V）。DAP 3.3V 供电导致面包板上"5V"实际是 3.3V——**必须万用表实测，不能只看标称** |
| 2 | **AT 自动配置思路是弯路** | 想上电用 AT 指令配 MODE2/信道，结果 +++ 时序、模式切换各种卡。官方例程根本不配 AT，模块保持默认透明模式(MODE0/信道00/速率2/密钥12345)直接收发 |
| 3 | +++ 进 AT 模式 | 受模块模式影响（AT+SWITCH=1 时引脚控制优先，+++ 可能无效）；重复 +++ 可能误退出 AT 模式 |
| 4 | **引脚冲突** | 原 LED2 在 PA2，和 LoRa USART2(PA2/PA3) 冲突，LED2 已挪到 PB0 |
| 5 | 接线照片识别 | 视觉识别两次结果不一致，不能全信，最终靠万用表（电压/导通）确认 |
| 6 | 回环测试定位法 | 短接 TX/RX 跑回环，能快速区分"MCU 串口坏"还是"模块/接线坏" |
| 7 | 帧解析兼容性 | 解析用"搜 ALM| 定位"而不是固定偏移，兼容信道字节前缀、带不带换行等情况 |

## 三、当前接线与引脚分配

| 功能 | 引脚 |
| --- | --- |
| 语音 JQ8900 串口 | PA9(TX) / PA10(RX) |
| 语音 BUSY | PA0 |
| LED1（灯条预留） | PA1 |
| LED2（调试小灯） | PB0 |
| LoRa USART2 | PA2(TX) / PA3(RX) |
| 调试串口 USART3 | PB10(TX) / PB11(RX) |
| 功放电源 MOS（预留） | PB1 |

音频链路：JQ8900 **DAC** → 功放 INL，JQ8900 GND → 功放输入 GND；功放 DC± 接 24V；喇叭接功放输出 L±。

## 六、2026-08-26 更新

### 1. 帧格式改为 `{dev_id,type,event}`

```
{N1,0,heartbeat}   数据帧（固定周期心跳）
{N1,1,landslide}   报警帧（事件开始/持续）
{N1,2,clear}       解除帧（事件结束）
```

- `LoRa.c` 按 `{}` + 逗号切分解析，回调 `LoRa_DataHandler(dev_id,type,event)`
- 主程序：type=1 响喇叭+灯亮；type=2 停止播报+灯灭；type=0 仅上传
- **不再做"全部节点才上报"判定**——所有帧都上传，由后台判断是否全报警

### 2. 4G 上传改为 M100MG-B1 DTU 透传

- 去掉 Air780E AT 驱动（g4g.c/h 已删除）
- STM32 用 **USART3(PB10/PB11, 115200)** 直连 DTU TTL 串口，把帧原样发给 DTU
- DTU 固件透传发布到 MQTT，后台订阅 topic 即收到
